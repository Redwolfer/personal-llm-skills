# QUICK workflow

Use one round for a perspective check. Read [Research.md](../Research.md), [CouncilMembers.md](../CouncilMembers.md), and [OutputFormat.md](../OutputFormat.md).

## 1. Research

Use a focused set of searches across primary sources, Reddit, X/Twitter, and other relevant sites. Apply Research.md's relevance, verification, and source-access rules. Keep the research table even when the session lacks browsing, and disclose the actual execution mode.

## 2. Brief members

Write four distinct briefs in English based on the question, user constraints, and findings. Each has a stable name, analytical role, stance, and speaking habit. Render the public roster in Indonesian.

## 3. Gather perspectives

Give each member its brief, relevant findings and source links, the topic, and user constraints. Ask for a grounded concern or recommendation in 80-120 words, with at least 80 unless the user requests a shorter format.

Use independent agents when available and permitted, or draft the perspectives separately in the current session. Record simulation honestly; do not imply independent verification.

## 4. Summarize and deliver

Write summary rows for consensus, concerns, and a recommendation. Use 120-200 words per row by default, with the minimum in OutputFormat.md unless the user requests less detail. Explain whether the evidence supports proceeding, reconsidering, or running a full DEBATE. Do not start extra rounds automatically.

Apply [Humanize.md](../Humanize.md), [GenZVoice.md](../GenZVoice.md), and the final evidence check to all public prose, including the summary. Use the complete bundled [Humanizer](../references/humanizer.md) in embedded mode. Publish no drafts or editing critiques.

Deliver the topic heading, research table, roster, perspectives table, and summary in that order using OutputFormat.md. End at the final summary row.
